## Java 21 (LTS)

**Что это.** Язык и платформа исполнения. LTS-релиз с долгой поддержкой.

**Зачем здесь.** Требование Spring Boot 3.x (минимум Java 17), а 21 — актуальный LTS
с record-классами, `switch`-паттернами и виртуальными потоками.

**Плюсы.**
- Свежий LTS: обновления безопасности несколько лет.
- Records и `var` дают короткий иммутабельный код (все доменные модели — `record`).
- Виртуальные потоки позволят без переписывания уйти от блокирующих вызовов под нагрузкой.

---

## Spring Boot 3.3.5

**Что это.** «Батарейки в комплекте»: стартеры, авто-конфигурация, встроенный Tomcat, управление версиями зависимостей.

**Зачем здесь.** Убирает ручную склейку: раньше конфиг читался через `System.getenv`, пул и HTTP-сервер поднимались руками.
Теперь достаточно `application.yml` и `@SpringBootApplication`.

**Плюсы.**
- Автоконфигурация: DataSource, Jackson, транзакции, health — из коробки.
- BOM фиксирует совместимые версии всех библиотек (jOOQ, PostgreSQL, Jackson).
- `spring-boot-maven-plugin` собирает исполняемый jar — не нужен shade-плагин.
- Готовые профили `application.yml` + плейсхолдеры `${VAR:default}` вместо самописных `AppConfig`.
- Огромная экосистема и документация.

**Минусы.** Магия авто-конфигурации: иногда неочевидно, откуда взялся бин. Лечится `--debug`.

---

## Spring Web MVC (starter-web)

**Что это.** Классический блокирующий веб-слой: `@RestController`, `@GetMapping`, `DispatcherServlet`.

**Зачем здесь.** Простые CRUD-эндпоинты — JSON туда, JSON обратно.

**Плюсы.**
- Декларативные маппинги, минимум кода.
- `@RestControllerAdvice` — единая обработка ошибок.
- Работает на виртуальных потоках Java 21.
- Отлаживается проще, чем реактивный стек (обычный стектрейс).

---

## Bean Validation (Hibernate Validator)

**Что это.** Стандарт `jakarta.validation`: `@NotBlank`, `@Email`, `@Size`, `@Positive`.

**Зачем здесь.** Валидация запросов объявлена на DTO, а не размазана по `if`-ам в контроллере.

**Плюсы.**
- Ограничения видны рядом с полем — самодокументируемый контракт.
- Ошибки автоматически превращаются в 400 с понятным текстом.
- Не зависит от фреймворка, тестируется отдельно (`Validator.validate(...)`).

---

## jOOQ 3.19

**Что это.** Библиотека типобезопасного SQL: вы пишете запросы на Java, а компилятор проверяет таблицы и колонки.
Код таблиц генерируется из `db/init.sql` на этапе сборки (`DDLDatabase`, база для сборки не нужна).

**Зачем здесь.** Нужен контроль над SQL и при этом мало кода — без ручных `PreparedStatement` и `ResultSet`.

**Плюсы.**
- Компилятор ловит опечатки в именах колонок; рефакторинг схемы ломает сборку, а не прод.
- Полный SQL: `RETURNING`, оконные функции, `JOIN` — без ORM-магии и N+1.
- Генерация из DDL — источник правды один (`db/init.sql`).
- Работает поверх обычного JDBC и HikariCP, легко профилируется (`LoggerListener`).

**Минусы.** Нужна пересборка после изменения схемы; DSL объёмнее, чем `@Query`.

---

## PostgreSQL 16

**Что это.** Реляционная СУБД.

**Зачем здесь.** Основное хранилище: пользователи, привычки, отметки.

**Плюсы.**
- `SERIAL`/identity, `RETURNING`, честные FK и `UNIQUE` — бизнес-правила держит БД.
- Предсказуемые транзакции и блокировки.
- Официальный образ в Docker с автоинициализацией из `init.sql`.
- Огромный набор типов (`DATE` для отметок), индексы, `pg_dump` для бэкапа.

---

## HikariCP

**Что это.** Пул соединений с БД (по умолчанию в Spring Boot).

**Зачем здесь.** Открывать TCP-соединение на каждый запрос — дорого.

**Плюсы.**
- Самый быстрый пул для JVM, минимальный оверхед.
- Настраивается одной секцией `spring.datasource.hikari.*`.
- Понятные метрики (`active`, `idle`, `timeout`).

---

## Spring Cloud Gateway

**Что это.** Реактивный API Gateway на Netty: маршруты по предикатам, фильтры, CORS.

**Зачем здесь.** Один вход на `:8080`; внутренние сервисы не публикуются наружу.

**Плюсы.**
- Маршруты и CORS — только YAML, ноль проксирующего кода.
- Фильтры из коробки: `DedupeResponseHeader`, retry, rate limiter, circuit breaker (подключается отдельно).
- Неблокирующий: держит много одновременных соединений малым числом потоков.
- Стандарт де-факто в Spring-мире — не нужен отдельный nginx только ради роутинга.

**Минусы.** Это ещё один контейнер; для одного сервиса хватило бы прямого доступа.

---

## Spring Cloud OpenFeign

**Что это.** Декларативные HTTP-клиенты: интерфейс с аннотациями, реализацию генерирует Spring.

**Зачем здесь.** `habit-service` проверяет пользователя, `tracking-service` — привычку.

**Плюсы.**
- Клиент — интерфейс в 5 строк, без `HttpClient` и ручного разбора JSON.
- Сериализация на `ObjectMapper` Boot; таймауты — в `application.yml`.
- Ошибки приходят типизированно (`FeignException.NotFound`), их удобно мапить в 404/422/502.
- Легко тестируется подменой бина.

**Минусы.** Скрывает сетевые вызовы — нужна дисциплина по таймаутам (по умолчанию они слишком большие, поэтому заданы явно).

---

## Spring Boot Actuator

**Что это.** Служебные эндпоинты: `/actuator/health`, `/actuator/info`, метрики.

**Зачем здесь.** Healthcheck'и в `docker-compose` и мониторинг.

**Плюсы.**
- `/actuator/health` сам проверяет БД — «UP» значит «сервис + база живы».
- `liveness`/`readiness` группы — сразу готово под Kubernetes, если понадобится.
- Подключается одной зависимостью, не требует кода.

## SLF4J + Logback

**Что это.** Фасад логирования и его реализация (по умолчанию в Boot).

**Зачем здесь.** Заменяет `slf4j-simple` из прошлой версии.

**Плюсы.**
- Уровни и паттерны настраиваются в `application.yml`.
- Один формат логов во всех сервисах, поддержка MDC (request id).
- Пишет в stdout — Docker сам собирает логи.

## Maven 3.9 (мультимодульный)

**Что это.** Сборщик и управление зависимостями.

**Зачем здесь.** Родительский `pom.xml` + 4 модуля; общие версии через `spring-boot-starter-parent`.

**Плюсы.**
- Один `mvn clean package` собирает всё, `-pl <module> -am` — только нужное.
- `pluginManagement` в родителе: конфиг jOOQ-кодогенерации не дублируется по модулям.
- BOM импортом (`spring-cloud-dependencies`) подключаются версии Spring Cloud.

## Docker + Docker Compose v2

**Что это.** Контейнеризация и описание стека одним файлом.

**Зачем здесь.** Поднять 5 контейнеров одной командой, с healthcheck'ами и сетью.

**Плюсы.**
- Multi-stage сборка: Maven-образ только на этапе билда, в рантайме — тонкий JRE-образ.
- Контейнеры работают под непривилегированным пользователем `app`.
- Healthcheck'и и `depends_on: condition: service_healthy` дают правильный порядок старта.
- Секреты — файлами (`POSTGRES_PASSWORD_FILE`, read-only mount), а не переменными окружения.
- Одинаково работает на ноутбуке и на сервере.

## JUnit 5 + AssertJ

**Что это.** Тестовый фреймворк и «текучие» ассерты (входят в `spring-boot-starter-test`).

**Зачем здесь.** Проверка валидации DTO и доменных правил.

**Плюсы.**
- `@Test`, `assertTrue`, `assertFalse` — читается как текст.
- Параметризованные тесты и `@Nested` для структуры.
- В том же стартере лежат Mockito и AssertJ — не нужно согласовывать версии.

---

## PlantUML

**Что это.** Диаграммы из текста (`.puml` → `.svg`).

**Зачем здесь.** Архитектура в git: диффы читаемые, картинки не устаревают молча.

**Плюсы.**
- Диаграмма — текстовый файл: ревьюится как код.
- Встроенный layout (Smetana) — Graphviz не нужен.
- Нет бинарных «скриншотов», которые забывают обновить.

## Почему именно так: короткие сравнения

| Вопрос | Выбор | Альтернатива и почему нет |
|--------|-------|---------------------------|
| Доступ к БД | jOOQ | JPA/Hibernate: абстракция мешает на `RETURNING` и сложных выборках; Spring Data JDBC: меньше контроля над SQL |
| Шлюз | Spring Cloud Gateway | Zuul — устарел; nginx — ещё один конфиг вне Java-экосистемы |
| Межсервисные вызовы | OpenFeign | `RestTemplate` — многословно; `WebClient` — реактивный, избыточен для блокирующего стека |
| Конфигурация | `application.yml` + PropertySource | `System.getenv` вручную — нет дефолтов, валидации и профилей |
| Секреты | файл + `spring.config.import` | переменные окружения — видны в `docker inspect` и `ps e` |
| Логирование | Logback | `slf4j-simple` — нет конфигурации и ротации |
| Сборка артефакта | `spring-boot-maven-plugin` | shade — конфликты ресурсов, ручной `mainClass` |
